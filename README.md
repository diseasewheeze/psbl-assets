# PSBL Assets

Official static asset and automation repository for the Pitch Slapped Baseball League.

This repository is public so Discord and Discohook can load approved images directly.

## Rules
- Keep the repository public.
- Keep the default branch named `main`.
- Do not rename live image files after webhook templates are in use.
- The approved PSBL primary logo is the master. Supporting assets must not redraw or reinterpret it.
- Discohook templates are one message per send: the channel's header banner embed (if any) plus one text embed, with extra sections merged in as bold divider fields. The banner keeps an invisible footer so Discohook accepts it; only the final embed has footer text and the gold divider image. The rules live in `tools/discohook_format.py`; `tools/normalize_discohook_templates.py` enforces them and the packaging workflow checks them.
- When several messages go out back to back into one channel (the 📜│constitution channel), only the last one has the footer text and divider (`SEQUENCES` in `tools/discohook_format.py`).
- Messages must read the same on desktop, tablet and phone: no inline fields, and section dividers and field names that fit a phone (`tools/discord_layout.py`).
- `discohook-backups/posted.json` records every template that is live in Discord, with a fingerprint of what was posted. A rebuild keeps the posted version instead of changing it, the checks fail if a posted template drifts, and the Send Console shows those rows as already posted. A posted message that has to change is listed under `update_in_place`, and the Send Console opens it as an **edit** of the live message (paste that channel's webhook URL in Discohook and press Edit), so nothing is deleted or reposted. See `tools/posted_messages.py`.
- Discord webhook URLs belong in GitHub Actions Secrets and must never be committed to the repository.

## Constitution
The Constitution (Preliminary Draft until the Commissioner finalizes it as the Charter) is generated from one source file:
`tools/constitution_source.py`. Its rules numbers (lineup, roster sizes, the pitcher-start and acquisition limits, minors limits, scoring) come from `automation/core/sport.py`, the same module every automation reads, so the rules text and the automations can't disagree.

Run `python3 tools/build_constitution.py --pdf` to rebuild everything from it:
- `constitution/PSBL_Constitution.pdf` and `.md` (owner-facing copies)
- `constitution/PSBL_Constitution_discohook_backup.json` (all Discord messages in one Discohook backup)
- `templates/constitution/` (one Discohook JSON per Discord message)


**Amendments and the changelog.** When an amendment passes (Article XX), change the article text in `tools/constitution_source.py` and add one entry to its `AMENDMENTS` list (date adopted, articles and sections, old text, new text, vote, effective Season; the comment above the list shows the format), then rebuild. The build writes `constitution/CHANGELOG.md` (every amendment by date, newest first, after the Charter's adoption by owner acceptance, effective Season 2027) and adds the dated entry to the history block at the end of Article XX. Amendments are identified by their adoption date; the build refuses entries that mention a version number, have fewer than 8 yes votes or more than 12 votes. With `AMENDMENTS` empty, rebuilding changes none of the Discord templates (a regression test checks this).

Per-channel intro messages are generated by `tools/build_channel_intros.py`.

## Automation architecture

The approved architecture is:

- **GitHub Actions = brain**, with timing owned by the **PSBL Scheduler**
- **Discord webhooks = delivery**
- **Fantrax = authoritative read-only league gameplay data where applicable**
- **Native integrations = use when superior**
- **Discord bot = save for a later interactive phase**

## League settings

League-wide settings live in `automation/league.yaml` (Fantrax league ID, season label, report time, playoff race start week, the light and heavy day thresholds for the MLB games grid, opted-in owners for pings, webhook secret names). `league_id` points at the Season 2027 Fantrax league; when the league renews, change `season_label`. Week dates, playoff weeks and playoff team count are read from Fantrax automatically.

The league's baseball rules live in `automation/core/sport.py`: the lineup (C, 1B, 2B, 3B, SS, 3 OF, 2 UTIL, 5 SP, 3 RP), bench, IL and minors sizes, the weekly pitcher-start and acquisition limits, the minor-league limits (130 career MLB at-bats, 50 innings) and the scoring values. `research/scoring/` holds the 2021 to 2026 player data and the analysis behind the scoring values (run values from FanGraphs' linear weights, at 10 points per run).

MLB data comes from MLB's public stats feed (statsapi.mlb.com, read-only): `automation/core/mlb.py` for the schedule, probable pitchers, scores and game content, and `automation/core/mlb_people.py` for players, career stats, game logs, 40-man rosters and transactions. Responses whose shape was not checked against a live response are marked in the code.

## Scheduling and the season calendar

All automation timing lives in one file: `automation/scheduler/schedule.yaml`.

The **PSBL Scheduler** workflow (`.github/workflows/league-scheduler.yml`) runs every 15 minutes, started by an external timer (cron-job.org) with GitHub cron as a backup. It starts each workflow in **live** mode when it is due and catches up after any delay, so a late check never skips a job.

Each job can be limited to parts of the season (preseason, regular season, playoffs, offseason). The current phase is worked out from Fantrax's own week dates, so the scoreboard and weekly report switch on when the season starts and the playoff bracket only runs during playoff weeks. Manual runs from the Actions tab ignore the calendar, so anything can be tested at any time. Setup and troubleshooting: `automation/scheduler/README.md`.

| Automation | When it runs |
| --- | --- |
| The Wire | Every 15 minutes, all year |
| League Office | Every 30 minutes, only while an enabled event is coming up |
| Automation Health | Hourly, all year |
| Competition Desk (weekly report) | 08:00 and 20:00 ET, preseason through playoffs; posts only when something is due |
| Live scoreboard | Hourly, regular season and playoffs |
| Lineup Alerts | 3:00 PM ET daily, regular season and playoffs |
| Probable Pitchers | 09:15, 11:45, 15:30, 18:15 and 21:30 ET, regular season and playoffs; edits one message a day |
| Morning Recap | 08:30 ET daily, all year; posts only after a day with MLB games |

| Draft Center | Every 15 minutes, only from 31 days before a Fantrax draft until a day after it ends |
| League Archive | Daily around 05:30 ET, all year |
| History Site | Daily around 06:15 ET, after the archive |

Shared Discord delivery (`automation/discord_webhook.py`) retries transient network failures, Discord rate limits and temporary HTTP errors, and can edit a message it posted earlier so live views update in place. Shared Fantrax and season-calendar code lives in `automation/core/`.

## The Wire

Source collectors, routing, persistent dedupe state, flood protection and webhook delivery live in `automation/wire/`; the sources are listed in `automation/wire/sources.yaml`. The scheduled workflow is `.github/workflows/league-wire-engine.yml`.

The scheduler starts the Wire every 15 minutes in **live mode**. When more stories arrive in one run than the flood guard allows as individual posts, the rest of each channel's stories are combined into one roundup post instead of being dropped. Manual workflow dispatch defaults to **shadow mode** for safe testing; shadow mode never posts to Discord.

- **Sources:** MLB's own transaction log (injured-list moves go to `🏥│injury-report`; recalls, options, selections, designations, trades, releases and signings to `🔄│mlb-transactions`), MLB.com and MLB Trade Rumors for news (CBS Sports as a discovery source only), FanGraphs and Prospects Live for `🌱│prospect-wire`, and five fantasy baseball podcasts for `📸│media`. ESPN, r/baseball and MiLB.com are listed but switched off, each with the reason, in `sources.yaml`. A feed marked `baseline_first: true` posts nothing on its first live run, so adding a feed never floods a channel with old stories.
- **Roster tags.** Stories about a player on a league roster show which franchise owns him, on every Wire channel. Players are matched by name and MLB club, so players who share a name are not confused; anything ambiguous is left untagged.
- **Owner pings (opt-in).** Owners listed under `owners` in `automation/league.yaml` are mentioned when one of their own players appears in the injury report. Nobody else can be pinged. The same list opts owners in to Lineup Alerts.

Operational and rollout instructions: `automation/wire/operations.md`.

## League Office

Commissioner-controlled dates and deadline reminders live in `automation/league-office/events.yaml`.

- Times are entered as New York wall-clock time; daylight saving is handled automatically.
- Reminders never post before their trigger. If a check runs late and several reminders are due at once (for example 3 hours, 1 hour and start), only the most recent one is posted and the older ones are skipped, so members never get a burst of stale countdowns.
- The scheduler only runs the League Office while an enabled event's reminder window is open (from an hour before its first reminder until the catch-up window after it starts). With every event disabled, it does not run at all.

**To turn on an event:** set its `starts_at` (e.g. `2027-09-20T20:00:00`) and `enabled: true`. Reminders start automatically.

## Competition Desk — weekly report

Code: `automation/competition/desk.py` · Workflow: `.github/workflows/league-competition-desk.yml`

Fantrax weeks run Monday through Sunday, so by Monday morning every game of the week is final. At **8:00 AM ET** that morning the Competition Desk posts, in order:

1. `📰│weekly-recap` — results of the week that just finished, with each team's **all-play** record (its record had it played all 11 other teams that week) for the week and the season
2. `📰│weekly-recap` — **Weekly Awards** (separate message)
3. `📰│weekly-recap` — **Power Rankings** with each team's **Luck** (separate message)
   - `📰│weekly-recap` — **Monthly Awards**, the morning the first week of a new month is reported (separate message)
   - `📰│weekly-recap` — **Bounty** claims, when a season bounty is first reached (separate message)
4. `📈│standings` — standings after that week (final standings after the last regular-season week)
5. `🏁│playoff-race` — from **Week 16** through the last regular-season week
6. Matchup preview for the week starting that day, with each matchup's **projected games** and **projected starts** (scoreboard channel)
7. **MLB games grid** for that week, for planning daily lineups (scoreboard channel, separate message)
8. **The Wooden Spoon** once a season, with the final regular-season standings: the last-place franchise takes the Spoon (`📰│weekly-recap`; its owner is mentioned if listed under `owners`). A league tradition with no money and no rule change; switch it off with `competition.wooden_spoon: false`

If Fantrax has not yet counted the finished week in its standings at 8:00 AM, standings and the playoff race wait and go out at the 8:00 PM check. Nothing is ever posted twice for the same week, and a failed post is retried automatically. Awards, rankings and the grid are tracked separately, so a failure in one never reposts the others.

All-play, awards and power rankings are results-only: they are computed from Fantrax's matchup scores for every final week of the season (`automation/competition/weekly.py`), so anyone can check them by hand. Weeks where every team scored 0 (placeholder weeks) and 0-0 matchups are ignored.

- **Power Rankings.** Score = 50% season points-for + 30% points-for over the last 3 final weeks + 20% season all-play win %. Both points-for figures are scaled 0 to 1 across the league (lowest team 0, highest 1); ties go to higher season points-for. Each team shows its rank, change since last week, record, points-for, season all-play, Luck and score. The posted ranks are saved in the report state so next week can show the change; if they are missing, last week's ranks are recomputed from the scores.
- **Luck Index** (in the Power Rankings, not part of the score). Expected wins (xW) add up each week's all-play win share: teams outscored that week ÷ 11, an equal score counting half. Luck = actual head-to-head wins (a tie counts half) − xW, shown to one decimal (`Luck +1.4`). One line names the luckiest and unluckiest teams. Across the league Luck adds up to 0.
- **Weekly Awards.** First, Second and Third Star (the top three scores), Tough Luck (highest score in a loss), Lucky Win (lowest score in a win), Closest Game and Biggest Blowout. These replace the recap's old High Score / Closest Matchup / Largest Margin lines, so the channel does not show them twice.
- **Not included: Bench Disaster and Waiver Steal.** Fantrax's read-only feed has no per-player daily points, bench points or waiver-claim results, so these two awards cannot be computed honestly. An endpoint with each player's fantasy points per period is on file with Fantrax as a feature request (October 2026), with no date.
- **MLB games grid.** Reads the MLB schedule for the Fantrax week and shows MLB clubs grouped by games played that week, doubleheaders, off days, light days (20 or fewer clubs playing) and heavy days (30 playing), plus two-start pitchers where the probable starters are known. Postponed games drop out and makeups count on their new date. Thresholds are `light_day_max_teams` and `heavy_day_min_teams` in `automation/league.yaml`.

- **Schedule edge** (in the matchup preview). For every day of the coming Fantrax week, each franchise's active hitter slots (C, 1B, 2B, 3B, SS, 3 OF, 2 UTIL) are filled from its ACTIVE and RESERVE hitters whose MLB club plays that day, using each player's Fantrax positions (a maximum matching, so a multi-position player goes wherever he lets the most players start). Starting pitchers count once per probable start, capped at the week's credited-start limit (Constitution 9.2). MINORS and IL players do not count. The line is left out when every roster is empty or anything cannot be read; the preview itself still posts (`automation/competition/edge.py`).
- **Monthly Awards** (`competition.monthly_awards`). A week belongs to the month its last night (Sunday, Constitution 5.8) falls in. The morning the first week of a new month is reported, `📰│weekly-recap` gets the previous month's awards: **Manager of the Month** (most points), **Best Record of the Month**, **Biggest Single Week** (a two-week period does not count) and **Hard Luck** (most points scored in losses). Ties go to more total points for the month, then are shared. The last regular-season month goes out with the final regular-season week. The Manager of the Month holds the `📅 Manager of the Month` role until the next award; the Commissioner moves the role by hand (`automation/competition/monthly.py`).
- **Bounties** (`competition.bounties`). One-time season goals, each claimed by the first franchise to reach it and announced once in `📰│weekly-recap` with the winner and the reward. Types: `team_season_points`, `team_week_points`, `team_win_streak` (checked when a week is final, from matchup scores) and `player_multi_homer` (a player with two or more home runs in a game, read from MLB's scoring plays the morning after; a hitter is credited to the franchise that rosters him, matched by name and MLB club like the Wire, and ambiguous names are skipped). Rewards are recognition only (default: the `🎯 Bounty Hunter` role for the Season, given by the Commissioner); a reward mentioning FAAB, picks, the draft, dues or money is rejected. Claims are saved in the report state, which the season rollover clears. Default thresholds were estimated from the league's scoring and should be checked against real weekly scores early in Season 2027 (`automation/competition/bounties.py`).

Manual runs can post or preview one item: `recap`, `awards`, `rankings`, `monthly`, `bounties`, `standings`, `race`, `preview` or `games`. In preview and test, `monthly` shows the month containing the chosen week (through that week, marked Month to Date when the month is not over), and `bounties` shows the Bounty Board: every claim so far and where each open bounty stands.

## Live scoreboard

Code: `automation/competition/scoreboard.py` · Workflow: `.github/workflows/league-fantrax-scoreboard.yml`

One scoreboard message per week in `📊│scoreboard`, posted when the week starts and **edited in place** every hour as scores change (edits do not notify members). Monday morning it gets a final update marked **Final** and stays in the channel as the record of that week.

Each team also shows **Pitcher starts: X of Y**. X is Fantrax's games-started count for the week; Y is the credited-start cap, 7 per calendar week (Constitution 9.2), so the two-week Championship gets 14 (9.3). Fantrax's own numbers decide what counts.

## Lineup Alerts

Code: `automation/lineup/alerts.py` · Workflow: `.github/workflows/league-lineup-alerts.yml` · Channel: `🔔│lineup-alerts` (webhook secret `LEAGUE_WEBHOOK_LINEUP_ALERTS`)

Once a day at about **3:00 PM ET** during the regular season and playoffs, each owner listed under `owners` in `automation/league.yaml` gets one short message that mentions them when:

- a hitter in today's **ACTIVE** lineup has no MLB game today while a **RESERVE** hitter who fits that slot does play (and his game has not started), or
- a starting pitcher in today's active lineup is not his club's probable starter today while a reserve SP is.

A pitcher is never flagged when his club hasn't named the day's starter. Owners not listed are never checked or pinged, each franchise gets at most one alert a day, and lineups remain each manager's responsibility (9.1).

- **Modes:** `preview` prints the alerts; `test` posts `[TEST]` alerts without notifying anyone; `live` alerts opted-in owners and records them.

## Probable Pitchers

Code: `automation/pitchers/probables.py` · Workflow: `.github/workflows/league-probable-pitchers.yml` · Channel: `⚾│game-day` (webhook secret `LEAGUE_WEBHOOK_GAME_DAY`)

On game days during the regular season and playoffs, the first check after **9:00 AM ET** posts one **Probable Pitchers** message: every MLB game today with both clubs' announced starters, or "Not announced". Starters on a league roster show their franchise. Later checks **edit that same message** when something changes (a late scratch, a doubleheader's second starter, a postponement), so nobody is notified. Information only: pitcher starts count against the weekly cap (9.2), and Fantrax's own numbers decide.

## Morning Recap

Code: `automation/media/morning.py` · Workflow: `.github/workflows/league-morning-recap.yml` · Channel: `📸│media` (webhook secret `LEAGUE_WEBHOOK_MEDIA`)

Every morning at about **8:30 AM ET** after a day of MLB games: **Last Night in MLB** (every final, winner in bold, extra innings and games called early marked, the winning, losing and saving pitchers, and links to the MLB.com recap and condensed game; postponed games listed at the end) and **The Home Run Reel** (home runs by players on league rosters, one field per franchise, with clip links where MLB's game content has them; left out when there are none). Links only, nothing re-uploaded, nobody pinged. Posted once per MLB date; a failed post is retried without repeats. Details: `automation/media/README.md`.

## Draft Center

Code: `automation/draft/` · Workflow: `.github/workflows/league-draft-center.yml`

Fantrax already tells owners when they are on the clock and shows every pick in the draft room, so the Draft Center never posts on-the-clock or per-pick messages. It covers what Fantrax does not:

- **📢│draft-announcements:** a countdown from the Fantrax draft date (30 days, 7 days, 1 day, 1 hour, and when it starts; the first post is the full announcement), the official draft order with any traded picks (7 days before, or on demand), a notice if the date or order changes, and a "Draft Complete" summary.
- **📋│draft-results:** the permanent record, posted round by round as each round is completed.
- **Commissioner Desk (private):** an alert when a pick clock runs out or a pick is skipped, with each team's timeout count (Articles 13.5 and 14.3).

The draft date, order, rounds and picks come from Fantrax; the pick clock and nightly pause come from `draft_center` in `automation/league.yaml`, because Fantrax does not publish them. Details: `automation/draft/README.md`.

## Trade Desk

Code: `automation/trades/` · Workflow: `.github/workflows/league-trade-desk.yml` · Channels: `💬│trade-discussion` (webhook secret `LEAGUE_WEBHOOK_TRADE_DISCUSSION`, **new**) and `📢│announcements` (`LEAGUE_WEBHOOK_LEAGUE_ANNOUNCEMENTS`, existing)

Every 30 minutes all year (every 15 on trade-deadline day) the Trade Desk compares Fantrax's rosters and draft-pick ownership with its last saved copy. Players and picks that moved straight from one PSBL team to another in that window are one trade (the archive's grouping, so a three-team deal is one trade); free-agent adds and drops are ignored. The first run for a league and season saves a baseline only. Two separate trades that share a team and go through minutes apart can't be told apart in the feed and show as one card; a card with three or more teams says so, and the Commissioner can correct it.

- **Trade report card** (`💬│trade-discussion`): one message per trade listing what each side received, with a native Discord poll **Who won the trade?** (each team, plus Even) open for 72 hours. The footer says the vote is just for fun and never affects the trade (Article XI). Owners still post the official record in `🚨│completed-trades`. If Discord ever refuses the poll, the card posts without it and the run log says so. A trade that exactly undoes one from the last 14 days (the Commissioner reversing it) gets no report card and no revisits. FAAB isn't in Fantrax's data feed, so it never shows. A trade seen after the trade deadline, while trading is closed (11.6: until the league is renewed for next season, the day after the World Series ends), gets a card without a poll saying the Commissioner reviews it under Section 11.6, and it doesn't count toward the season's trades. A trade first seen in the check right after the deadline keeps its poll and counts, with a line that the Commissioner checks it was processed in time.
- **Trade revisit at 6 and 12 months** (same channel, around noon ET on the day): for each side, the fantasy points its players have produced in MLB regular-season games since the trade, wherever they have played since (MLB game logs, hitting and pitching, scored with the league's values in `automation/core/sport.py`); picks show "not yet used" or the player drafted with them when the league archive has that draft; and the final poll result, read back from Discord. It never suggests a trade should change. Trades from a TEST season are never revisited in a real one.
- **PSBL Deadline Day Trade Center** (`📢│announcements`): on trade-deadline day (the Sunday that ends Week 20, deadline 11:59 PM ET, from the Fantrax calendar with the same helper the League Bot's `/tradecheck` uses) one message is posted at 9:00 AM ET and edited every 15 minutes: a live countdown, every trade seen that day and the number of trades this season. The first run after the deadline turns it into the final "Deadline passed — N trades today".
- **Manual Deadline Day Trade Center templates** (Send Console, "Deadline Day Trade Center"): a Trade Bait board forum post for `📣│trade-block` and the Deadline Day Trade Center Sesh event text for `📅│league-calendar`.
- **Modes:** `preview` prints what would be posted (add `at`, e.g. `2027-08-15T21:00`, to preview deadline day); `test` posts one `[TEST]` sample: `card` (with a 1-hour poll, then reads it back from Discord), `revisit` or `tracker` (posted, then edited to its final state); `live` detects, posts and saves; `rebaseline` reads Fantrax and saves it as the new snapshot without posting anything. Run `rebaseline` once after a deliberate roster reset (the Commissioner emptying a team, a TEST draft re-run): `live` refuses that as an incomplete Fantrax answer and its error says to.
- **Safety:** state is saved after detection and after every post, and the workflow's save step runs even if the job fails or times out, so a card is never posted twice. Revisits run last, after the tracker, and stop at a 6-minute budget for MLB reads; the rest resume next run. A Fantrax error keeps the saved snapshot, still runs cards, the tracker and revisits, and fails the run so the health monitor sees it. A player who moved with nothing coming back isn't posted when the window since the last good Fantrax read is longer than 3 hours and includes the daily waiver run (a waiver drop and a FAAB claim would look the same); the new rosters become the baseline and the log says so. If draft picks can't be read while players moved, nothing is posted until a later run (for up to 6 hours), so a player-for-pick trade stays one card. Picks in a draft Fantrax has set up are read too, so pick trades around the Annual Draft are seen.
- **Setup:** in Discord, copy the existing `💬│trade-discussion` webhook's URL and add it as the repository secret `LEAGUE_WEBHOOK_TRADE_DISCUSSION`. Until it is set, report cards and revisits are skipped with a log line and the run still succeeds.

## League history

Code: `automation/history/` · Site builder: `tools/build_site.py`

Fantrax keeps no league history across seasons and its read-only feed has no transaction log, so the PSBL keeps its own.

**Daily archive** (workflow PSBL League Archive, `league-archive.yml`, daily around 05:30 ET, all year; modes `preview` and `live`). Each run saves to `archive/` on the `automation-state` branch, one folder per Fantrax season (`seasonYear`, so renewing the league never overwrites anything):

- the latest roster snapshot (player ID and status per team) and draft-pick ownership;
- `events.jsonl`, an append-only log of transactions inferred by comparing today's snapshot with the last one: adds from the pool, drops to the pool, moves into or out of MINORS and IR, and trades. Players and picks that moved directly between teams in the same run form one trade listing what each side received, so a three-team deal is one trade. Daily ACTIVE/RESERVE lineup changes are not recorded;
- final scores for every finished week (re-read for three days to catch stat corrections), final regular-season standings once Fantrax has counted the last week, and the draft results once a draft is complete.

The first run of each season saves a baseline only. Limits: a player dropped by one team and claimed by another between two runs looks like a trade with nothing going back (it is flagged as one-sided), and an add and drop within the same day is never seen. A run that gets an obviously incomplete roster list from Fantrax saves nothing and fails, and the restore step refuses to start from an empty copy if the state branch exists but can't be fetched. Seasons labeled TEST in `league.yaml` (a test league) count as history only until the first real season is archived; after that they stay in the archive but drop out of every record and the site automatically.

**History data file** (`automation/history/history.yaml`). The Commissioner records what the feed can't know: franchise identities (name, owner display name, Season founded, colors, optional logo path, and every Fantrax team ID the franchise has used), each Season's champion, runner-up, third place, Presidents' Trophy, consolation champion and Wooden Spoon, and the Dynasty Pot money (dues added, unused operating reserve added, optional running balance). Championship counts in the active Dynasty Pot cycle are worked out from the champions (Article IV: first to 3 titles in a cycle wins the pot, then the counters reset); if you fill in the counts or balances anyway, the check makes sure they agree. The file starts empty with commented examples, and the regression tests validate it on every change.

**Rivalries.** Lifetime head-to-head records (regular season and playoffs) come from the saved weekly results. Declare rivalries under `rivals:` in `automation/league.yaml` (empty by default). Every franchise also has an earned rival: the opponent it has played most, closest record breaking ties. `history.rivals.rivalry_note(team_a_id, team_b_id, archive)` returns a one-line note such as "Rivals: lifetime 3-2-1" for the weekly preview to use (not wired in yet).

**Trade trees** (`history/trades.py`). For each side of a trade, every asset received is followed forward: traded again (and what came back), dropped, a pick used in a saved draft (and the player taken), or still on the roster.

**Manual posts** (workflow PSBL History Posts, `league-history-posts.yml`; choose `item` and `mode`: `preview` builds everything and attaches the images to the run, `test` posts one `[TEST]` message, `live` posts):

| Item | Posts to | Secret |
| --- | --- | --- |
| `dynasty-pot` | One `💰│league-ledger` message in the Dynasty Pot update format, with a PNG of the balance and every franchise's titles this cycle | `LEAGUE_WEBHOOK_LEAGUE_LEDGER` (new) |
| `franchise-cards` | One `🏒│franchise-directory` message per franchise, each with a card: name, owner, founded, titles, Dynasty Pot count, rival | `LEAGUE_WEBHOOK_FRANCHISE_DIRECTORY` (new) |
| `draft-retro` | A retrospective of a saved draft (latest by default, or `draft_year`) to `📋│draft-results`: biggest steal, biggest miss, best undrafted pickup, best development. Images are drawn with Pillow (`automation/history/requirements.txt`) in the league's navy, red and white and attached to the message, so nothing is committed. Retrospectives score MLB regular-season stats since the draft with the league's scoring values.

**History website** (workflow PSBL History Site, `league-history-site.yml`, daily plus manual; `preview` attaches the built site to the run, `live` publishes it). A standalone public website on **Cloudflare Pages** at the league's own domain. `tools/build_site.py` builds it from main plus the archive on the `automation-state` branch as plain HTML and CSS with no JavaScript. It uses the league's 8-bit look in navy, red and white. Every page, sprite and font (Jersey 10, Silkscreen and Pixelify Sans in `brand/fonts/`, SIL Open Font License) is served by the site itself, and nothing on it names or links to GitHub; the regression tests fail the build if anything does.

- **Pages:** home (championship banners in the rafters, the Dynasty Pot race, season by season), a page per Season (honors, standings, every week), a page per franchise (banners, season by season, head-to-head, trades, draft picks), head-to-head and rivalries, trades with trade trees, drafts with retrospectives, league records, and the Constitution with its changelog. Clean addresses such as `/seasons/2027/` and `/franchises/rink-rats/`, plus a 404 page, `robots.txt`, a sitemap and a link-preview image.
- **Address:** `history_site.url` in `automation/league.yaml` (for search engines and link previews) and `history_site.cloudflare_project` (default `psbl-history`, free address `https://psbl-history.pages.dev` until the domain is connected).
- **Security and speed:** a `_headers` file gives Cloudflare a strict content security policy and long caching for versioned assets.
- It builds cleanly from an empty archive. Build it locally with `python tools/build_site.py --archive <archive folder>`; output goes to `site/` (git-ignored). Preview it with `python -m http.server -d site` and open http://localhost:8000. It shows franchise names, owner display names and league results only.

## League Bot

`bot/` holds the always-on PSBL League Bot: league votes (proposals, one vote per franchise, Commissioner elections, Review Panel draws, suggestion threads turned into proposals), `/rule` Constitution lookup, `/deadlines`, `/minor` eligibility checks, a private `/myteam` view, `/tradecheck` compliance checks and a weekly Pick'em. It reads Fantrax and never writes to it. It is built and tested but not deployed; it goes on Railway once owners join. Setup and commands: `bot/README.md`.

## Where bot state lives

Automations remember what they have already posted (Wire dedupe, report weeks, the live scoreboard's message, playoff seeds, health issues). That state, and the league archive (`archive/`), is kept on the separate **`automation-state`** branch, not on `main`, so `main` only contains code and content changes. Each workflow restores its state at the start of a run and saves it back at the end (`automation/tools/state_branch.sh`). State is saved even when one post in a run fails, so successful posts are never repeated.

## Regression checks

Automation regression tests cover the season calendar (against Fantrax week dates), Fantrax error handling, the MLB stats client (schedule, probables, doubleheaders, postponements, finals and game content, against MLB-shaped fixtures), the weekly report (all-play, power rankings, the Luck Index and weekly awards), Monthly Awards, bounties, projected games and starts for the matchup preview, pitcher starts on the live scoreboard, the MLB games grid and Lineup Alerts, Probable Pitchers, the Morning Recap, playoff seeding and reseeding, scheduler due-time logic and retries, Wire routing and roundup posts, the health monitor, shared Discord retry behavior, League Office timing, the league archive, `history.yaml`, Dynasty Pot cycles, trade trees, rivalries, draft retrospectives, the history graphics, posts and website, the Constitution changelog, the Trade Desk (trade detection, the report card poll, revisit scoring from MLB game logs, deadline-day timing and the live tracker), minor eligibility by MLB career totals, and the League Bot (votes, `/rule`, `/deadlines`, `/minor`, `/myteam`, `/tradecheck`, Pick'em). The regression workflow compiles every automation module and runs these checks whenever relevant code or configuration changes.

The MLB-shaped Fantrax fixtures are synthetic until the real league exists; once it does, capture real responses with `tools/fantrax_probe.py` and check club codes, slot names (UT or UTIL), positions and the games-started category against them.
